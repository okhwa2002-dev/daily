# 개발 규칙 문서

이 폴더는 `daily` 프로젝트의 개발 규칙을 영역별로 나눠 관리한다.
루트 `CLAUDE.md`에서 `@` 임포트로 연결되어 세션 시작 시 함께 로드된다.

## 문서 목록

| 파일 | 내용 |
|---|---|
| [database.md](database.md) | 테이블 공통 컬럼, 날짜/시각, 소프트 삭제, 소유권 격리, 멱등 업서트, 인덱스, 네이밍 |
| [project-structure.md](project-structure.md) | 기술 스택, 디렉터리 구조, 아키텍처 원칙 |
| [security.md](security.md) | 비밀값 관리, 인증, 로그, 개인정보 |

## 작성 중인 문서

설계가 확정되는 대로 추가한다. 미확정 내용을 미리 적어두지 않는다.

| 예정 파일 | 다룰 내용 |
|---|---|
| `sync.md` | 동기화 프로토콜, 아웃박스 큐, 충돌 해결, 재시도 정책 |
| `backend.md` | Fastify 라우트/서비스 분리, 요청 검증, 에러 응답 형식 |
| `frontend.md` | 컴포넌트 작성 규칙, Zustand 사용 범위, Dexie 쿼리 패턴, 스타일 |
| `testing.md` | 테스트 계층별 범위, 오프라인 시나리오 e2e |

## 규칙 문서 작성 원칙

- 하나의 파일은 하나의 영역만 다룬다.
- "무엇을" 뿐 아니라 **"왜"** 를 함께 적는다. 이유를 모르면 규칙은 지켜지지 않거나 잘못 적용된다.
- 결정되지 않은 내용은 적지 않는다. 미확정이면 그렇다고 명시한다.
- 규칙이 바뀌면 문서를 고친다. 코드와 문서가 어긋나면 문서가 먼저 신뢰를 잃는다.
